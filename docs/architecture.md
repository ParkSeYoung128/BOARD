# 스키마 · 구조 · 라우팅 설계 (v1)

## 1. DB 스키마 (Flyway `V1__init.sql`)

```sql
CREATE TABLE posts (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  title       VARCHAR(20)  NOT NULL,          -- 코드포인트 기준 20자
  content     TEXT         NOT NULL,
  author      VARCHAR(50)  NOT NULL,
  like_count  INTEGER      NOT NULL DEFAULT 0 CHECK (like_count >= 0),
  created_at  TIMESTAMPTZ  NOT NULL,          -- 초 단위 절삭 값
  deleted_at  TIMESTAMPTZ
);
CREATE TABLE comments (
  id          BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  post_id     BIGINT       NOT NULL REFERENCES posts(id),
  content     TEXT         NOT NULL,
  author      VARCHAR(50)  NOT NULL,
  created_at  TIMESTAMPTZ  NOT NULL,
  deleted_at  TIMESTAMPTZ
);
CREATE TABLE post_likes (
  post_id     BIGINT       NOT NULL REFERENCES posts(id),
  user_id     VARCHAR(50)  NOT NULL,
  created_at  TIMESTAMPTZ  NOT NULL DEFAULT now(),
  PRIMARY KEY (post_id, user_id)
);
-- 부분 인덱스(JPA로 선언 불가 → Flyway SQL)
CREATE INDEX idx_posts_feed        ON posts    (created_at DESC, id DESC)              WHERE deleted_at IS NULL;
CREATE INDEX idx_comments_by_post  ON comments (post_id, created_at DESC, id DESC)     WHERE deleted_at IS NULL;
```
- 시드 id를 그대로 넣기 위해 `GENERATED BY DEFAULT`(명시 id 허용). 적재 후 `setval`.
- Hibernate는 `ddl-auto=validate` — 스키마의 진실은 Flyway.
- 삭제 표시는 `deleted_at`(삭제 시각을 남길 수 있고 `IS NULL` 부분 인덱스에 유리).

## 2. 백엔드 구조 (`io.github.parkseyoung128.board`)

```
post/      PostController · PostService · PostRepository · Post(entity) · PostSummary(DTO record)
comment/   CommentController · CommentService · CommentRepository · Comment(entity)
like/      LikeService · PostLikeRepository(JDBC/@Modifying)
seed/      SeedLoader (SmartInitializingSingleton — 웹 서버 기동 전 적재, JdbcTemplate batch, `app.seed-enabled`로 끌 수 있음)
common/    RequesterResolver(HandlerMethodArgumentResolver) · Cursor · ApiExceptionHandler · ApiError
```
- 쓰기: 엔티티 행위 메서드(`Post.create/edit/softDelete`, `assertOwner`) + 서비스 트랜잭션.
- 읽기: JPQL **DTO 프로젝션**(commentCount·isLiked를 서브쿼리로) — 연관관계(`@OneToMany`) 미사용, 컬렉션 fetch join 금지.
- 소프트 삭제: `@SQLRestriction("deleted_at is null")` + 엔티티 `softDelete()` 메서드(@SQLDelete 미사용). 네이티브/JDBC 경로는 조건을 명시.
- 좋아요·시드: 원자적 SQL (JPA 우회, README에 근거 기록).
- 설정: `spring.jpa.open-in-view=false`, `ddl-auto=validate`, Jackson 시각 형식 고정. `isLiked`는 `@JsonProperty("isLiked")`로 키를 명시.

## 3. 프론트엔드 구조 (`frontend/`)

### 스택 (결정 사항)
| 영역 | 선택 | 비고 |
| --- | --- | --- |
| 프레임워크 | Next.js 15 App Router, React 19, TypeScript | 고정 스택. 개발 서버만 `next dev --turbopack`, 빌드는 기존 `next build` 유지 |
| 서버 상태 | TanStack Query | `useInfiniteQuery`, 낙관적 업데이트 |
| UI 전역 상태 | Zustand | 토스트 한정 |
| 스타일링 | Tailwind CSS v4 (`@theme` 토큰) | 디자인 토큰은 `docs/design-tokens.md` |
| 모달·바텀시트 | Radix UI Dialog (`@radix-ui/react-dialog`) | 포커스 트랩·ESC·aria를 위임. shadcn CLI는 쓰지 않고 필요한 컴포넌트만 직접 작성 |
| 폼 검증 | **직접 구현** (react-hook-form·zod 미사용) | `canSubmit = 제목 코드포인트 1~20자 && 내용 비어있지 않음`. 붙여넣기도 코드포인트 기준으로 절단 |
| 폰트 | Pretendard Variable | 제공된 `globals.css` 유지 |

```
app/
  layout.tsx            Providers(QueryClient) · Toaster · 375px 셸
  page.tsx              목록
  posts/[id]/page.tsx   상세
  posts/[id]/edit/page.tsx   수정(작성 폼 재사용)
  write/page.tsx        작성
  dev-user/             (수정 금지)
features/
  posts/   api.ts · queries.ts(useInfiniteQuery, mutations) · PostCard · PostForm · PostMenuSheet
  comments/ api.ts · queries.ts · CommentItem · CommentComposer
shared/
  api/client.ts         fetch + credentials + 에러 타입
  ui/                   Header · Icon · Avatar · InfiniteSentinel · Toaster
                        ConfirmDialog (Radix Dialog) · BottomSheet (Radix Dialog 변형)
  store/toast.ts        Zustand 토스트 스토어
  lib/                  time.ts · number.ts · avatar.ts · codepoint.ts (제목 길이 계산)
```
- 데이터 호출은 **클라이언트**(쿠키 전달이 단순, 상호작용 중심). API 주소는 `NEXT_PUBLIC_API_BASE_URL`.
- 서버 상태는 TanStack Query 캐시가 유일한 출처. 키: `['posts']`(무한), `['post', id]`, `['comments', id]`(무한).
- UI 상태: 모달/시트 열림·입력값은 컴포넌트 로컬 `useState`, **토스트만 Zustand 스토어**(라우트 전환 후에도 유지, 새로고침 시 재노출 없음).

### 라우팅·흐름
| 동작 | 결과 |
| --- | --- |
| 목록 카드 클릭 | `/posts/{id}` |
| FAB 클릭 | `/write` |
| 작성 완료 | `toast.show("게시글이 등록되었습니다.")` → `router.replace('/')` — 토스트는 Zustand 스토어 |
| ⋯ → 수정하기 | `/posts/{id}/edit` (기존 제목·내용 채움) → 저장 후 `/posts/{id}`로 복귀 |
| ⋯ → 삭제하기 → 예 | 삭제 후 `router.replace('/')` · 아니오는 상세 유지 |
| 댓글 삭제 → 예 | 캐시에서 제거, 댓글 수 갱신 |
| 없는/삭제된 글 접근 | 안내 문구 + 목록으로 이동 버튼 |

### 시간 표기 (`shared/lib/time.ts`, 순수 함수 · 단위 테스트 필수)
| 대상 | 규칙 |
| --- | --- |
| 목록 | 항상 상대: 방금 전(<1분) / N분 전 / N시간 전 / N일 전(1–6일) / N주 전(7–29일) / N개월 전(30–364일) / N년 전 |
| 댓글 | **30일 미만은 상대**(위와 동일), 그 이후는 `yy.MM.dd` |
| 상세 본문 날짜 | 항상 `yy.MM.dd` (시안) |
- 날짜 포맷은 `Asia/Seoul` 고정. 숫자는 `toLocaleString('ko-KR')`(1,411).
- 요구사항 요구: 목록의 상대 시간. 상세·댓글의 전환 기준(30일)은 **자율 구현** → README 기록.

## 5. 테스트 전략

| 층 | 도구 | 검증 대상 |
| --- | --- | --- |
| 백엔드 통합 | JUnit 5 · Spring Boot Test · **Testcontainers(PostgreSQL 16)** | 삭제 정책(글·댓글·삭제된 글의 댓글 비노출), 권한(403/404), 검증(코드포인트 20자·공백), keyset 순회(댓글 1,411개 무중복·순서·같은 초 동률), 좋아요 토글·동시성, 쿼리 수(N+1), 시드 재적재 idempotency |
| 프론트 단위·컴포넌트 | Vitest · React Testing Library | `time.ts` 경계값(59초/60초, 23시간/24시간, 6일/7일, 29일/30일, 364일/365일), `codepoint.ts`, 작성 폼 활성 조건, 댓글 더보기 노출 조건(`total > 2`), 본인 글·댓글에서만 메뉴·삭제 표시 |

- 백엔드 통합 테스트는 Docker가 필요하므로 Docker가 있는 환경에서 `./gradlew test`로 실행한다. 프론트 단위·컴포넌트 테스트와 빌드·타입체크는 Docker 없이 실행된다. 브라우저 E2E는 작성하지 않았다(README "남은 과제").
