# 실험: 서브에이전트로 동시성 결함을 미리 찾을 수 있는가

개발하면서 사람이 하나씩 찾아 고쳤던 동시성 결함 4건이 있었습니다. 결함이 고쳐지기 **전** 코드에 서브에이전트를 돌렸을 때 몇 건을 찾는지, 그리고 지시문만 바꾸면 결과가 어떻게 달라지는지 측정했습니다.

## 결과 요약

| 결함 (정답지 `answer-key.md`) | A안 일반 지시 | B안 체크리스트 |
| --- | --- | --- |
| D1 같은 사용자의 좋아요 연타 경합 (CI를 깨뜨린 결함) | ✕ "안전하다"고 판정 | ○ 단, 심각도를 "낮음"으로 판단 |
| D2 글 수정·삭제가 `like_count`를 덮어씀 | ○ | ○ |
| D3 글 삭제 중 댓글 작성 | ○ | ○ |
| D4 수정이 삭제를 되돌려 글이 되살아남 | ○ | ○ |
| **탐지** | **3/4** | **4/4** |
| 오탐 | 0 | 0 |
| 추가 발견(경미) | 3건 | 2건 |

- 일반 지시만으로도 AI는 4건 중 3건을 찾았습니다. 놓친 1건이 하필 실제로 CI를 깨뜨린 결함이었고, 에이전트는 이를 "안전"이라고 단정했습니다.
- 체크리스트를 주자 4건을 모두 찾았습니다. 그러나 D1의 심각도는 여전히 "낮음"이었습니다. 찾는 일은 AI가 하더라도, 무엇을 볼지 기준을 세우고 진짜 문제인지 판정하는 일은 사람이 필요했습니다.
- B안 에이전트는 `CLAUDE.md`의 `like_count` 기준(기록 수와 일치)과 API 계약서의 기준(시드 초기값 + 기록 수)이 다르다는 문서 불일치도 짚어냈습니다.

채점 상세와 원문: [`results/record-template.md`](./results/record-template.md), [`results/A_basic.txt`](./results/A_basic.txt), [`results/B_checklist.txt`](./results/B_checklist.txt) (Claude Code 대화 내보내기 원문, 이름만 정리).

## 한계 (결과를 읽을 때 꼭 알아야 할 것)

- **각 안 1회 실행**입니다. LLM 결과는 실행마다 달라질 수 있어, 3/4와 4/4의 차이가 통계적으로 유의하다고 말할 수 없습니다.
- **체크리스트는 결함을 알고 난 뒤에 설계했습니다.** B안의 "ORM 변경 감지가 바꾸지 않은 컬럼까지 UPDATE하는가", "소프트 삭제는 FK가 막아 주지 않는다" 같은 항목은 이미 겪은 결함 유형에서 나왔습니다. 따라서 B안의 4/4는 "처음 보는 결함도 찾는다"가 아니라 **겪은 교훈을 체크리스트로 만들면 에이전트가 재사용할 수 있다**는 근거입니다.
- 같은 모델(Opus 5.5)·같은 프로젝트 규칙(`CLAUDE.md`)에서 지시문만 바꿨습니다. 지시문 외의 변수(모델, 도구)는 통제했지만 표본이 작습니다.
- 정답지 채점은 제가 직접 했습니다.

## 실험 설계

- **대상**: 결함 4건의 원인 코드가 모두 존재하는 시점의 스냅샷(`snapshot/`, 원본 개발 이력의 커밋 `ed7779f` 기준). 이후 커밋과 완성된 README는 넣지 않았습니다(`git archive`로 추출). 이 시점에도 에이전트가 쓴 좋아요 테스트(홀수 연타 포함)가 이미 있었습니다.
- **통제 변수**: 지시문만 다릅니다.
  - A안 `race-hunter-basic`: "경합을 찾아라" 수준의 일반 지시
  - B안 `race-hunter-checklist`: 쓰기 경로 목록 만들기 → 모든 쌍 점검 → 체크리스트(확인 후 실행, 읽고-수정-쓰기, 다단계 연산, 소프트 삭제, 격리 수준, 락 종류) 적용 → 안전한 조합도 근거와 함께 기록
  - 공통: 도구는 `Read, Grep, Glob`만, 코드 수정·테스트 실행 금지, 출력은 같은 표 형식
- **오염 방지**: `.claude/hooks/guard.py`(PreToolUse 훅)가 스냅샷 밖 파일 읽기, Bash 실행, 파일 수정을 차단합니다. 새 세션에서 실행했고, 프롬프트에는 결함 힌트(연타, 되살아남, 덮어쓰기 등)를 넣지 않았습니다.
- **채점**: 정답지의 "탐지 인정 기준"을 만족하면 ○, 정답지에 없는 보고는 실제 문제인지 판정해 오탐과 추가 발견으로 따로 셌습니다. 실험이 끝난 뒤에만 정답지를 열었습니다.
- **실행 환경**: Claude Code v2.1.285, Opus 5.5, 2026-10-05 (A안 12:44, B안 12:51).

## 직접 재현하기

```bash
cd experiments/race-hunt/snapshot
claude          # 새 세션으로 시작 (--continue, --resume 사용 금지)
```

처음 실행 시 이 폴더의 `.claude/settings.json`(훅)을 신뢰할지 물으면 허용하고, `/agents`로 두 에이전트가 보이는지 확인한 뒤 아래 문장을 그대로 입력합니다. 각 실행 사이에는 `/clear`를 합니다.

> race-hunter-basic 서브에이전트를 사용해 이 저장소 백엔드의 동시성 경합을 찾아 줘. 결과는 에이전트가 낸 표를 그대로 보여 줘.

> race-hunter-checklist 서브에이전트를 사용해 이 저장소 백엔드의 동시성 경합을 찾아 줘. 결과는 에이전트가 낸 표를 그대로 보여 줘.

`answer-key.md`는 모든 실행이 끝난 뒤에 여세요. 스냅샷 안의 `docs/`와 소스는 이름만 정리했고 구조는 원본 그대로입니다. 단, 원본의 `SeedLoader`는 이 스냅샷 시점에 아직 없었습니다(에이전트도 "시드 적재는 검토하지 못했다"고 보고했습니다).

## 이 실험이 프로젝트에 남긴 것

- B안 지시문과 체크리스트는 `.claude/agents/race-hunter-checklist.md`와 `.claude/skills/race-check/SKILL.md`로 재사용 자산이 되었습니다.
- "에이전트는 git을 하지 않는다", "실험 중 저장소 밖을 읽지 않는다" 같은 규칙을 말이 아니라 훅(`guard.py` → `.claude/hooks/`)으로 강제하는 방식을 프로젝트 전반에 적용했습니다.
- 문서 간 기준이 어긋나면 에이전트가 먼저 짚어낸다는 점을 확인해, 불변식을 `AGENTS.md`에 한 곳에 모았습니다.
